## Plan Review: Improve the skills for output quality, token cost, and subagent use

**Verdict:** REVISE

Six lenses (Usability/DX, Architecture, Correctness, Test Coverage, Portability, Performance/Cost) ran against the plan and against the real files. The structural diagnosis is genuine and unusually well-researched — `inheritSkills: false` really does break three fan-outs, the Codex export really does drop `AUDIT_STRATEGY.md`, and Pi's packaged agents really are as described. But on the question you asked — *does this improve skill output quality?* — the honest answer is **no, not much**: roughly 1.5 of 8 phases change what the model produces, four reduce cost, and two reduce cost at plausible unmeasured cost to quality. Three defects are blocking: Phase 1 and Phase 5 disagree about where reference files live (Phase 5 ships silently broken on Codex), Phase 2's host ladder has no host-detection mechanism yet gates verification-skipping on it, and Phase 6 breaks the byte-identity test Phase 2 introduces. Separately, the plan's own citation layer is unreliable — five `SKILL.md:NN` references point at the wrong content and two of those are edit instructions.

### Answering the question you asked

**Will the skills produce better output?** Partially, and unmeasurably as written.

| Phase | Changes output quality? |
|---|---|
| 1 — Codex export fix | Yes, but only on Codex, and only as on/off (`testing-strategy` currently loses the 450-line reference its body calls mandatory) |
| 2 — Portable fan-out | One real win: dropping the arbitrary 4-5 child cap that the plan itself diagnoses as "one child doing two jobs worse". Rest is portability |
| 3 — Self-contained child prompts | **Yes — the single best thing in the plan.** Children currently get "apply the DRY dimension" with the rubric unreachable, and `testing-strategy` tells a child to "answer that level's questions below" where "below" is not in its context |
| 4 — Named agents, delegated verification | Cost. Carries quality *risk* (see below) |
| 5 — Progressive disclosure | Cost, ~700 tokens. Negligible |
| 6 — `agents/` definitions | Infra |
| 7 — Evals | Measurement, but of the wrong property, and sequenced last |
| 8 — Pi host tuning | Cost (dollars) |

Three things specifically work against output quality and are not acknowledged:

- **Phase 3's `No issues found.` rule deletes the honesty mechanisms.** `code-quality-audit:125-126` mandates an "Explicitly fine" section ("an audit with findings everywhere isn't credible"); `testing-strategy:151-152` mandates "Explicitly not recommended… it keeps the audit honest"; `review-plan:52-57` asks children for strengths. A child contractually limited to `No issues found.` cannot feed any of them, and the new schema has no strengths field.
- **Phase 4 takes its saving out of the noise-suppression mechanism.** `research-codebase:65-67` — "read enough of each cited file to confirm the claim… **Drop or downgrade** anything that doesn't survive that check" — is a *calibration* pass, not a string check. A `sed -n 'X,Yp'` window confirms the quote, not the claim, and `evidence-auditor` under `inheritSkills: false` has no idea what these skills consider a finding worth keeping.
- **Nothing targets the parent's synthesis** — `review-plan` §4, `code-quality-audit` §4, `research-codebase` §5-6. That is the part you actually read.

And the prose-scope decision at lines 124-126 ("Body sizes are healthy… so this plan does not trim prose") is a non-sequitur. Word count is evidence about length, not clarity. The *outcome* is mostly right — most of this prose is genuinely good — but the reasoning can't distinguish the well-written skills from the badly-written one, and it lets `remove-comment-slop:89` through (one ~90-word paragraph carrying ~12 separate directives) and `create-plan:18-21` (a child prompt with no return format, no evidence bar, no empty-result rule — strictly worse than the three Phase 3 fixes, and excluded from Phase 3).

### Cross-Cutting Themes

1. **Phase 1 and Phase 5 contradict each other on file layout** (Architecture, Test Coverage, Portability, Performance — 4 lenses). Phase 1 inlines every `*.md` **sibling** of SKILL.md; Phase 5 puts references in a `references/` **subdirectory**. All four Phase 1 tests stay green while Phase 5 silently deletes six rubrics from Codex — reintroducing the exact defect Phase 1 exists to fix.
2. **The host ladder has no host** (Architecture, Correctness, Portability, Usability). The skills are byte-identical on every host; nothing tells the model which one it is in. Phase 2 nonetheless gates *skipping verification* on that inference, and Phase 4's guard test actively removes the unconditional fallback phrasing.
3. **"Quality" is never defined, and the one metric is gameable in the direction the plan pushes** (Usability, Test Coverage, Performance). "Every `path:line` resolves to a real line" is citation *integrity* — a report of twenty resolvable citations of twenty non-issues scores 100%, as does a report with zero findings. It is precision-only with no recall counterpart, while Phase 4 explicitly relaxes verification.
4. **The plan's own citations are unreliable** (Correctness, verified independently). Five wrong; two are edit instructions.
5. **Pi lock-in with a portability veneer** (Portability, Architecture, Performance). Every Phase 4 lever is Pi-only; three of four hosts read four bullets of Pi API detail they cannot use. The OpenCode branch is "use its subagent mechanism if present" — and OpenCode is not installed on this machine at all.
6. **Three cost budgets used interchangeably, prompt caching absent** (Performance, Test Coverage). Parent context, total tokens, dollars billed — the plan switches between them per paragraph. Pi children are `context: fresh` + `inheritSkills: false`, so every child is a guaranteed cache miss while the parent is a cache hit — which inverts "children are cheap relative to parent context" in dollar terms.

### Findings

#### Critical

- 🔴 **Architecture / Test Coverage**: Phase 1's sibling-only walk misses Phase 5's `references/` subdirectory — **Location**: Phase 1 Changes bullet 3 vs Phase 5 Changes — Phase 1 specifies "every `*.md` **sibling** of `SKILL.md`" and tests a flat fixture; Phase 5 creates `references/solid.md` etc. A flat glob won't match. PR 1 and PR 4 each pass their own tests; the combination regresses Codex to zero rubric content. The Phase 1 spec is also internally contradictory — "sibling" implies a flat glob but "skip anything under `scripts/`" only makes sense for a recursive walk. Fix: make Phase 1 recurse `**/*.md`, and add the `references/` fixture test in PR 1 as its contract with PR 4.
- 🔴 **Portability / Architecture / Correctness**: Phase 2 gates verification-skipping on a host identity nothing establishes — **Location**: Phase 2 Changes, "No mechanism available (Codex)" — `install_one` injects no host marker; the Codex prompt file never says "you are Codex". A Pi run that serialises, or a Claude Code run that mis-reads itself, silently drops the citation discipline. Fix: either stamp the host at install time (free for Codex — that file is already generated) or restate the rule capability-conditionally: *"if you read the cited files yourself in this session, skip the re-read; if a child reported them, verify."* That needs no host knowledge and is correct everywhere.
- 🔴 **Architecture**: Phase 6 breaks Phase 2's byte-identity test — **Location**: Phase 6 Changes bullet 5 vs Phase 2 Tests — Phase 6 adds "prefer the bundled agent by name" to the shared block, but bundled agents are *per-skill* (`cq-dimension`, `test-level`, `plan-lens`). A per-skill name cannot live in a block asserted byte-identical across five skills. PR 5 lands on a red test, and the likely resolution under pressure is deleting the test — removing the only drift protection the strategy has. Fix: split the block into an invariant shared section and a declared per-skill child roster, testing each appropriately.
