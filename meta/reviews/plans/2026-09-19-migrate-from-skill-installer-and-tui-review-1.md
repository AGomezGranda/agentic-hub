## Plan Review: Migrate skill-installer into agentic-hub, split into modules, add a Textual TUI
**Verdict:** REVISE
The module split (catalog/agents/cli), phase boundaries, and TUI scope are sound and well-reasoned — Phase 1 and Phase 3 are low-risk and effectively ready as written. Phase 2, the only phase that mutates real `$HOME` state and deletes source in another repo, has a verified factual gap (`skill-installer` has no `.git`, confirmed via `git rev-parse --is-inside-work-tree` → "not a git repository") that invalidates its stated revert mechanism, plus an unconditional `rm` of Codex prompts that bypasses the tool's own ownership check. Several lenses also independently found the same `cli.py` migration-inventory gap (`resolve_agents()` dropped from the bullet list) and the same Phase-1 success-criteria mismatch for the `codex` agent's status.

### Cross-Cutting Themes
- **`resolve_agents()` missing from the `cli.py` migration bullet** — flagged independently by Architecture, Code Quality, and Correctness. Same underlying gap: the Phase 1 `cli.py` bullet enumerates every function moved except this one, and no test would catch it dropping.
- **The `catalog`/module-qualified-import lesson isn't consistently carried through** — Architecture (Finding 1, re: `cli.py`), Code Quality (Finding 2, re: `tui.py`/`AGENTS`), and Correctness (Finding 3, re: `test_agents.py` using raw reassignment instead of `monkeypatch.setattr`) are all variations on "the Phase 1 fix for one staleness hazard needs to be applied everywhere the same pattern recurs."
- **Phase 2's own `### Changes` bullets don't inline-gate on Success Criteria passing** — Code Quality and Safety both note the deletion/rm steps read as a flat sequence, with the "verify first" ordering only stated in prose elsewhere in the doc.

### Findings

#### Critical
- 🔴 **Safety**: `skill-installer` deletion has no working revert path — **Location**: Phase 2 Changes / PR Strategy step 2 — Verified independently: `/Users/alvaro.gomez/code/skill-installer` has no `.git` directory (`git rev-parse --is-inside-work-tree` fails). The plan's stated safety net ("its own commit... independently revertable") doesn't exist for this repo. Deleting `install.py`, `test_install.py`, and `DESIGN.md` there is permanent. `DESIGN.md` in particular has no migration destination anywhere in Phase 1 — its content (problem statement, deliberately-skipped rationale, open questions) is simply lost.

#### Major
- 🟡 **Safety**: unconditional `rm` of Codex prompts bypasses the tool's own ownership check — **Location**: Phase 2 Changes, the `rm ~/.codex/prompts/{...}.md` line — This is a raw shell command, not a call through `agents.py`/`remove_one`, so it skips `is_our_codex_file()` entirely. The "pure generated artifacts" justification is asserted, not verified against the actual files before deletion.
- 🟡 **Safety**: no verification that Phase 1's copied skill content still matches source before Phase 2 deletes it — **Location**: Phase 1 Changes (skills copy) vs. Phase 2 Changes (skills delete) — across a multi-day, multi-PR rollout, an edit to `skill-installer/skills/` between the two phases would be silently lost with no VCS to recover it.
- 🟡 **Test Coverage**: Phase 3's new CLI dispatch branch (bare `agentic-hub` → TUI, subparsers becoming non-required) has zero test coverage — **Location**: Phase 3 Changes (`cli.py` bullet) vs. Phase 3 Tests — `test_tui.py` only exercises `tui.py` directly via `App.run_test()`, never `cli.main()`/`build_parser()`. This is genuinely new branching logic, not a mechanical port, and nothing asserts a bare invocation reaches the TUI or that `list`/`install`/etc. still parse correctly once subparsers are optional.
- 🟡 **Correctness**: Phase 1 success criteria wrong for the `codex` agent — **Location**: Phase 1 Success Criteria (Automated) vs. `install.py`'s `status()` — the plan predicts `stale`/`missing` across the board after the migration, but renaming `CODEX_MARKER` means the real `~/.codex/prompts/*.md` files (old marker) will report `conflict`, not `stale`/`missing`, per `status()`'s own `mode != "symlink"` branch. The plan already reasons about this exact mismatch in Phase 2 but doesn't carry the conclusion back into Phase 1's stated expectation — whoever runs the Phase 1 check will see `codex: conflict` and may think something broke.

#### Minor
- 🔵 **Architecture / Code Quality / Correctness** (merged): `resolve_agents()` omitted from the Phase 1 `cli.py` migration bullet — **Location**: Phase 1 Changes, `src/agentic_hub/cli.py` — `cmd_install`/`cmd_remove` call it directly; it has no home in `catalog.py`/`agents.py`. Low risk since it'll obviously be needed, but the plan's own "confirm it's a mechanical split" success criterion is exactly where an incomplete inventory could let something get dropped or duplicated.
- 🔵 **Architecture**: `cli.py`'s import style for `catalog` isn't specified with the same rigor as `agents.py`'s — **Location**: Phase 1 Changes, `cli.py` bullet — if `cmd_list`'s `SKILLS_DIR` reference becomes a bare `from .catalog import SKILLS_DIR`, it reintroduces the same staleness class of bug the plan explicitly fixed for `agents.py`, just cosmetic in impact (a print message) today.
- 🔵 **Architecture**: no stated import strategy (top-level vs. lazy) for `tui` inside `cli.py` — **Location**: Phase 3 Changes, `cli.py` bullet — if `textual` is imported eagerly, every scripting invocation (`list`/`install`/`remove`/`sync`) pays its import cost even though those paths never touch the TUI.
- 🔵 **Architecture**: `prog="install.py"` not mentioned for rename — **Location**: Phase 1 Changes, `cli.py` bullet ("Logger name becomes...") — `argparse.ArgumentParser(prog="install.py")` is moved verbatim per the bullet's own wording, so `agentic-hub --help`/errors would still say `usage: install.py ...` unless `prog=` is updated too, alongside the logger/marker/entry-point renames the plan otherwise tracks carefully.
- 🔵 **Code Quality / Correctness** (merged): ported tests use raw global reassignment (`catalog.SKILLS_DIR = ...`, `agents.AGENTS = ...`) instead of pytest's `monkeypatch.setattr` — **Location**: Phase 1 Tests, `tests/test_agents.py` — safe today only because every planned test resets its own fixture up front; becomes an implicit cross-file ordering invariant once `test_catalog.py`/`test_tui.py` share a pytest session, where `monkeypatch` would make isolation structural instead of by convention, at no extra line cost.
- 🔵 **Code Quality**: Phase 3's `AGENTS` monkeypatch may not reach `tui.py`'s column-building code — **Location**: Phase 3 Changes/Tests, `tui.py` — if `AgenticHubApp` does `from .agents import AGENTS` instead of referencing `agents.AGENTS`, the DataTable's columns reflect the real 4 agents at import time, not the test fixture's fake one, and `test_tui.py`'s row-count assertion would fail. Self-catching during implementation, but worth stating explicitly to skip the debug detour.
- 🔵 **Code Quality**: Phase 2's deletion step isn't inline-gated on its own Success Criteria — **Location**: Phase 2 Changes vs. Context — the "only after verified" ordering lives in the Context section, not as a note on the deletion bullet itself; someone executing Changes top-to-bottom could delete before verifying.
- 🔵 **Safety**: same gating gap, safety framing — **Location**: Phase 2 Changes — reiterates the above from a data-loss angle; fix is one inline phrase ("only after Success Criteria below pass") on the deletion bullet.
- 🔵 **Test Coverage**: `test_tui.py`'s install/remove fixture uses only one fake agent — **Location**: Phase 3 Tests — can't distinguish "installs to the one agent" from "installs to all agents"; a two-agent fixture would actually exercise the fan-out the `i` binding claims to implement.

#### Suggestions
- 🔵 **Architecture**: the `if mode == "symlink" else (codex)` branching repeated across 3 functions is fine at n=2 agents but is the one seam a 3rd write-strategy would need to touch 3 places for — worth a `ponytail:`-style comment at the branch point, no action needed now.
- 🔵 **Architecture**: packaging skills under `src/agentic_hub/skills/` (wheel-bundled) removes any future override point (env var, user-level skills dir) — not a regression, but worth one acknowledging line since nobody's asked for user-authored skills yet.
- 🔵 **Code Quality**: no stated feedback path for install/remove conflicts inside the TUI's alternate screen buffer — stderr logging is invisible while the app runs; the status cell staying non-`linked` is the de facto signal but isn't stated as intentional.
- 🔵 **Test Coverage**: `parse_frontmatter`'s second edge case (opened-but-unclosed frontmatter, `len(parts) < 3`) isn't in the Phase 1 test list alongside the no-frontmatter case that is.
- 🔵 **Test Coverage**: `cli.py` gets zero tests in Phase 1 (parity with the original suite, not a regression) — `resolve_agents`'s `sys.exit` on an unknown agent is a cheap, high-value one-liner to add given the fixture already exists.
- 🔵 **Correctness**: Phase 3's zero-skills edge case is stated in Tests but not echoed as an implementation requirement (empty-table guard) in Changes.
- 🔵 **Correctness**: `discover_skills()`'s `if not SKILLS_DIR.is_dir(): return []` branch isn't in the planned test list — pre-existing gap, cheap to add while already rewriting this file.
- 🔵 **Safety**: a trivial `cp -r skill-installer /tmp/skill-installer-backup-$(date +%s)` before the destructive step is near-free insurance independent of whether `git init` happens.
- 🔵 **Safety**: the `rm ~/.codex/prompts/{...}.md` line uses bash/zsh brace expansion — fine as written, just note it needs an interactive bash/zsh shell if ever copy-pasted elsewhere.

### Strengths
- ✅ Module split (`catalog.py` reads sources, `agents.py` writes targets, `cli.py` wires them) matches the real responsibility boundaries in `install.py`, with no circular dependencies.
- ✅ The `from . import catalog` (module-qualified) vs. `from .catalog import SKILLS_DIR` distinction is correctly identified and reasoned about for testability, mirroring the original `test_install.py` pattern.
- ✅ `CODEX_MARKER` rename's Phase 2 consequence (stale prompts read as foreign) is explicitly pre-analyzed rather than left as a runtime surprise.
- ✅ Phase separation by blast radius: Phase 1 touches no real state, Phase 2 is isolated and revertable-in-intent, Phase 3 is purely additive and reuses `agents.py`/`catalog.py` with no duplicated logic.
- ✅ Test suite migration correctly ports the 3 original scenarios to plain pytest `tmp_path`, drops the hand-rolled runner, and adds a genuine new edge case (no-frontmatter) the original never covered.
- ✅ Phase 3's TUI scope is disciplined — explicit "add only if the MVP feels limiting" list of deferred features (multi-select, agent filter, theming).
- ✅ `install_one`'s existing don't-clobber-what-we-don't-own guard is preserved verbatim and stays test-covered.
- ✅ Phase 2 correctly fences off unrelated `risk-ai-infra`-sourced symlinks as out of scope.

### Recommended Changes
1. Before Phase 2 runs: establish an actual revert mechanism for `skill-installer` — `git init` + commit its current state, or at minimum a timestamped backup copy — and fold any still-relevant `DESIGN.md` content into `agentic-hub` before deleting it (addresses: Safety-critical-1).
2. Replace the blind `rm ~/.codex/prompts/{...}.md` with a check that each file's first line still matches the *old* marker before deleting (addresses: Safety-major-1).
3. Add a diff check (`diff -r skill-installer/skills agentic-hub/src/agentic_hub/skills`) to Phase 2's Success Criteria, gating the deletion on it being empty (addresses: Safety-major-2).
4. Add `resolve_agents()` to the Phase 1 `cli.py` migration bullet (addresses: Architecture/Code Quality/Correctness merged minor).
5. Correct Phase 1's Success Criteria to expect `conflict` (not `stale`/`missing`) for the `codex` agent specifically (addresses: Correctness-major).
6. Add a CLI-level test for the Phase 3 dispatch change (bare invocation → TUI; existing subcommands still parse) beyond the `tui.py`-only smoke test (addresses: Test Coverage-major).
7. Inline "(only after Success Criteria below pass)" on Phase 2's deletion bullet (addresses: Code Quality-minor, Safety-minor).
