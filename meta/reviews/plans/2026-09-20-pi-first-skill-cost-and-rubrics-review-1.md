## Plan Review: Four-host skill tuning — host truth, per-host prose, real serial path, better rubrics
**Verdict:** REVISE

Five lenses (Architecture, Correctness, Code Quality, Test Coverage, Portability) ran against the plan and against the real files (`agents.py`, the skill/agent frontmatter, `tests/test_*.py`, and the installed `pi-subagents` docs). The plan is unusually well-researched — nearly every line citation and factual claim checked out exactly against the real files, a marked improvement over the prior plan's five wrong citations. But two mechanisms it proposes don't work as designed: Phase 2's "symlink hosts become generated files" is a materially bigger architectural change than described and no test exercises the mixed state it creates, and Phase 6's "full body in file, index in chat" contract is impossible for the three read-only agents it targets given how Pi persists `output:` for tool-less-write children. Both were independently caught by 2-4 lenses each, from different angles, which is strong convergent signal rather than one reviewer's opinion.

### Cross-Cutting Themes

1. **Phase 2's architecture gap — flagged by all five lenses.** `agents.py` today has exactly two install modes: `symlink` (one `Path.symlink_to` per whole skill *directory*) and `codex` (one flattened *file*). Phase 2 needs a third thing — a directory that's part generated (`SKILL.md`), part symlinked/copied (`references/*.md`, `scripts/`) — that the `Mode` type, `status()`, and `remove_one()` have no representation for. This is the single most load-bearing finding in this review.
2. **Two claims restate a personal machine setting as an architectural fact — Architecture, Code Quality, Portability.** "`scout` resolves to `defaultModel: claude-sonnet-5`" is true only because this machine's `settings.json` happens to set that default; the docs describe inheritance from "your current Pi default model," not a fixed value. Doesn't change the recommendation, but the plan should say so.
3. **Phase 5's `defaultReads: context.md` on `repo-scout.md` — Correctness, Portability.** That field is for reading an *upstream* agent's output before starting (the `worker.md` pattern); `repo-scout.md` already declares `output: context.md` as its *own* artifact. As written, a scout would try to read a file it hasn't written yet, or pick up another run's stale one.
4. **Tradeoff, not a defect:** Phase 6's index/body split, once fixed to work at all, is Pi-only in practice (Portability) — Claude Code's generic children have no `output:`-file convention, so the phase's "Pi and Claude Code" scope claim only has an enforcement mechanism on one of the two.

### Findings

#### Critical

- 🔴 **Correctness / Code Quality**: Phase 6's return contract cannot be produced by the agents it targets — **Location**: Phase 6, Changes — `cq-dimension.md`, `test-level.md`, `plan-lens.md` all declare `tools: read, grep, find, ls, contact_supervisor` — no write tool. Per `pi-subagents/docs/tool-reference.md:174`, a read-only-tool child's `output:` file *is* its final message, persisted verbatim — there is no mechanism to write a long body to the file while returning a short index in chat. Whichever the model does, the two documents Phase 6 wants (full body on disk, index in chat) collapse into one. The phase's stated goal — "a spot-check tier finding is judged from its index line alone... never read the file whole" — cannot be met with the current tool allowlists as specified. Needs a different mechanism (e.g. `outputMode: "file-only"`, and the parent doing its own extraction) before PR 7 is written.

- 🔴 **Architecture / Correctness / Code Quality / Portability / Test Coverage**: Phase 2's "symlink hosts become generated files" is a bigger, untested architectural fork than described — **Location**: Phase 2, Changes (`_splice_fanout(body, host)` / "same machinery" claim) — Today's `symlink` mode links the *entire skill directory* in one `Path.symlink_to` call (confirmed by `test_agents.py::test_install_symlinks_native_agents`); `codex` mode generates one flattened file. There is no existing concept of "symlink everything in this directory except one spliced file." Concretely, if Phase 2 ships as described: `status()`'s `symlink` branch requires `tp.is_symlink()`, so a generated (non-symlink) `SKILL.md` sitting where a symlink used to be reports `"conflict"`, not `"linked"`/`"stale"`; `remove_one()`'s `symlink` branch also requires `tp.is_symlink()`, so it silently no-ops and orphans the generated file on removal. None of Phase 2's proposed tests (`test_splice_injects_only_host_branch`, `test_symlink_host_detects_stale_after_source_edit`) build a fixture host directory containing both a spliced skill and a plain-symlinked skill side by side, and neither touches `remove_one()`. The "Success criteria" checklist item that would catch this (`agentic-hub list shows linked for all skills`) is a manual CLI step, not a test — a regression here would not fail CI. This is worth a design paragraph (does the installer copy the directory per host, or symlink siblings individually and generate only `SKILL.md`?) before PR 2, which the plan itself already calls the riskiest, silent-regression PR in the whole plan.

#### Major

- 🟡 **Architecture**: Phase 4b's claimed Codex benefit isn't delivered by the described change — **Location**: Phase 4b — `_bundled_references` walks `skill_dir.rglob("*.md")` and inlines *every* markdown file except `SKILL.md`/`scripts/`/`assets/`, regardless of how many files a reference is split into. Splitting `AUDIT_STRATEGY.md` into `overview.md` + six level files doesn't reduce what a generated Codex prompt inlines — `_codex_body` still concatenates all seven, at roughly the same total length plus new per-file headers. The split is real value for Pi/Claude/OpenCode (each level child gets only its file); the plan should not also claim it as a Codex win, since Codex has no fan-out to hand a subset to.

- 🟡 **Correctness / Portability**: `defaultReads: context.md` added to `repo-scout.md` targets the agent's own output file — **Location**: Phase 5, Changes, final bullet — `repo-scout.md` already declares `output: context.md`; `defaultReads` is documented and precedented (`worker.md`) as reading a *different, upstream* agent's already-written output before starting, not an agent's own future artifact. Phase 5 dispatches `repo-scout` as parallel, cold-context children with nothing writing a `context.md` first. Best case this is a silent no-op; worst case a scout in a shared working directory picks up a stale `context.md` from a prior run and treats it as unverified ground truth. Reads like the `agents.md` illustrative example copied without adapting it.

- 🟡 **Correctness**: Phase 2's spliced Pi branch adds `async: true` with no wait step — **Location**: Phase 2, "Pi's spliced branch" code block — `async: true` makes the top-level `subagent` call return a background-run receipt immediately; the `await runs.all([...])` inside the workflow completes on its own schedule, not in the same parent turn. Nothing in the branch (or the skills consuming it) tells the model to `bg_wait`/poll before synthesizing. The current, pre-plan prose doesn't mention `async` for this call shape at all — this is a new problem the plan introduces while fixing something else, not a defect it's fixing.

- 🟡 **Code Quality**: The load-bearing "project discovery already reaches this repo's `agents/**/*.md`" premise looks unverified and possibly false — **Location**: Context, Gap 2; Phase 1 rationale for `agentScanDirs` — per `pi-subagents/docs/configuration.md:9`/`agents.md:24`, project settings and project-agent discovery resolve from the nearest parent directory containing `.pi` or `.agents`. This repo has neither. If that's the actual resolution rule, Pi's ordinary project discovery may never have reached this repo's `agents/*.md` even from inside it — meaning Gap 2's "already reaches... inside this repo" half, not just the "outside this repo" half Phase 1 fixes, could be false today. Worth one runtime check (`subagent({action:"list"})` from inside the repo under today's settings) before treating this as settled.

- 🟡 **Test Coverage**: Phase 5's proposed roster-test change targets a text window that structurally excludes the content Phase 5 adds — **Location**: Phase 5, Tests, referencing `test_fanout_roster_line_present_per_skill` — the existing test slices only the text between the `### Fanning out` heading and the first `- **Pi**` bullet. Phase 5 inserts its `repo-scout` recon-delegation paragraph *before* §1's/§2's bullets — well above that heading. "`FANOUT_ROSTER` accepts `repo-scout` as a second permitted name" implies a small dict tweak, but as written the existing test cannot see text placed there regardless of that tweak. Either the test needs new slicing scoped to §1/§2, or the insertion point needs to move.

- 🟡 **Portability**: Phase 6's "Pi and Claude Code" scope has no enforcement mechanism on Claude Code — **Location**: Phase 6, Overview and Changes — `agents/*.md` files are Pi-only reachable (per this repo's own `test_agent_definitions_have_valid_frontmatter` and the plan's "What we're NOT doing"). Claude Code's children are generic built-in `Agent`/`Task` types with no `output:`-file concept and no shipped agent definitions. Phase 6 names no change to the Claude Code fan-out branch that would give its generic children an equivalent write-then-index convention, so the contract it builds is Pi-only in practice even though the phase claims both hosts benefit.

#### Minor

- 🔵 **Architecture / Code Quality / Portability**: "Resolves to `defaultModel: claude-sonnet-5`" states a personal machine setting as a fixed fact — **Location**: Context, Gap 2 — the cited doc text describes inheriting "your current Pi default model," not a hardcoded value; it's `claude-sonnet-5` only because this machine's `settings.json` sets that top-level default. Doesn't change the recommendation (the override is still correct today) but should be flagged as environment-contingent, the same category ponytail calls a calibration knob rather than an axiom.
- 🔵 **Architecture**: Gap 8's anti-trigger count is off by one — **Location**: Context, Gap 8; Phase 7c — six of seven descriptions lack a "Not …" clause (only `code-quality-audit` has one), not five. Phase 7c's scope line should say six.
- 🔵 **Correctness**: Claude Code's "children cannot nest" claim is presented as verified but is uncited — **Location**: Context, capability matrix — every other cell in a table headed "(verified here unless noted)" cites a doc line, a `which` check, or a repo file; this one is asserted flatly. Likely true, but Phase 3 repeats it as a hard constraint and it deserves the same "unverified" tag OpenCode gets.
- 🔵 **Code Quality**: Phase 4b's split doesn't say where `AUDIT_STRATEGY.md`'s §8 "Audit heuristics" (cross-level rules) go — **Location**: Phase 4b table — the table names only `overview.md` and per-level files; dropping §8 loses real guidance, bolting it onto one level file gives that child material it shouldn't need. Belongs in `overview.md` explicitly.
- 🔵 **Portability**: `agentScanDirs` still hardcodes an absolute path the prior plan's review already flagged — **Location**: Phase 1a — `"~/code/agentic-hub/agents"` breaks silently on a different clone path or a worktree; carried forward unchanged with no acknowledgment or mitigation.
- 🔵 **Portability**: Phase 1's cost fix is entirely unversioned and untested — **Location**: Phase 1, Tests ("None... outside the repo") — no `agentic-hub` command touches `settings.json`; a fresh machine or contributor runs `agentic-hub sync`, gets all seven skills linked, and silently keeps paying Sonnet prices for recon until someone manually transcribes the README's JSON block. Same category as the prior plan's own Phase 8 critique of itself.
- 🔵 **Test Coverage**: `evidence-auditor`'s Haiku override has no success criterion, "what to notice," or revert condition of its own — **Location**: Phase 1a — bundled alongside `scout`'s well-justified override in a phase whose stated principle is "one lever per PR"; if Haiku weakens evidence-auditor's judgement, nothing in Phase 1 is positioned to catch it.
- 🔵 **Test Coverage**: `test_single_severity_vocabulary` (Phase 7b) doesn't match what the phase actually ships — **Location**: Phase 7b — the phase keeps *two* vocabularies by design (children get P0/P1/P2, the report keeps critical/major/minor for the reader); a test named for "single" vocabulary is ambiguous about what it verifies.
- 🔵 **Test Coverage**: `test_dimension_rubrics_are_substantive`'s "bad and good example marker" is undefined — **Location**: Phase 4 Tests — no heading text or delimiter convention is named anywhere in 4a, risking six independently-written rubric files with inconsistent formatting against an ambiguous test.
- 🔵 **Architecture**: Phase 4a's rubric fattening has an unacknowledged Codex cost tradeoff — **Location**: Phase 4a — growing six reference files 5-8x multiplies what gets inlined into the Codex prompt (~40-50 → ~240-360 lines) on the one host with no fan-out to amortize it against; the phase's success criteria never name this.

#### Suggestions

- 🔵 Merge the `AGENTS` per-host fan-out key with the existing agent key rather than adding a field that, today, would just restate it (`pi`→`pi.md`, `claude`→`claude.md`, etc.) — only useful if a future case actually diverges.
- 🔵 State Phase 2's "read on demand" revert path honestly: it still requires the model to know which host it's running as to pick the right reference file, a smaller version of the ambiguity problem Gap 1 exists to remove.
- 🔵 Give OpenCode's re-verification a forcing function (dated follow-up, tracked issue) — right now it's a manual bullet with no owner, easy to leave stale indefinitely.
- 🔵 Adopt "extend/add the test first, confirm it fails for the right reason, then edit the prose" as a one-line PR-strategy convention — it would have surfaced the Phase 2 and Phase 5 test gaps above during plan-writing itself.

### Strengths

- ✅ Citation accuracy is high across all five lenses — line ranges, byte counts, agent frontmatter, and Pi doc references were independently verified and held up almost everywhere, a marked improvement over the prior plan's five wrong citations.
- ✅ The concurrency/model-resolution "open questions" from the prior plan are genuinely answered with real evidence (`globalConcurrencyLimit`/`maxSubagentSpawnsPerRun` docs, `agentScanDirs` precedence, `scout`/`evidence-auditor` frontmatter).
- ✅ One-lever-per-PR discipline with explicit "what to notice" and "revert if" per phase is a real state-safety mechanism given the plan's own admission that there's no automated quality signal.
- ✅ Fail-loud design instinct: Phase 2 makes a missing per-host branch file a hard install-time error rather than a silent fallback; Phase 3 requires named degradation instead of silent truncation on serial hosts.
- ✅ Good reuse: Phase 4a points at an existing in-repo pattern (`remove-comment-slop/references/examples.md`) instead of inventing a new rubric format; "What we're NOT doing" forecloses real scope creep with reasons, not assertion.

### Recommended Changes

1. **Resolve Phase 2's install-mode gap before PR 2.** Decide explicitly between (a) copying the skill directory per host and generating `SKILL.md` inside the copy, or (b) generating `SKILL.md` and individually symlinking every sibling file — then extend `Mode`, `status()`, and `remove_one()` to represent it, and add a test with a mixed spliced/plain-symlinked host directory plus a `remove_one()` case. (addresses: critical finding 2)
2. **Fix Phase 6's return contract mechanism.** Either give the three agents a write tool plus explicit "don't rewrite the repo" scoping, or use `outputMode: "file-only"` with the full document as the one artifact and have the parent do its own index-line extraction — the current "index in chat, body in file" split cannot exist for a read-only-tool child. (addresses: critical finding 1)
3. **Fix or drop `defaultReads: context.md` on `repo-scout.md`.** It targets the agent's own output file; either remove it or point it at whatever upstream artifact a scout is actually meant to read first. (addresses: major finding 3)
4. **Add a wait step to Phase 2's Pi branch**, or drop `async: true` from that specific call shape, so the model doesn't try to synthesize from a background run it never waited on. (addresses: major finding 4)
5. **Verify project-agent discovery from inside this repo before relying on it in Gap 2 / Phase 1.** One `subagent({action:"list"})` check settles whether `.pi`/`.agents` marker absence actually breaks in-repo discovery today. (addresses: major finding 5)
6. **Fix Phase 5's test plan** to insert the `repo-scout` delegation text where `test_fanout_roster_line_present_per_skill`'s slice can see it, or scope a new slice rule to §1/§2. (addresses: major finding 6)
7. **Narrow Phase 4b's stated Codex benefit to Pi/Claude/OpenCode**, and separately note Phase 4a's Codex-side prompt-size cost. (addresses: major finding 1, minor finding on 4a)
8. **Soften "resolves to claude-sonnet-5" and the anti-trigger count to match verified reality** (six descriptions lacking a "Not…" clause, not five), and cite or tag "children cannot nest" for Claude Code the same way OpenCode's uncertainty is tagged. (addresses: minor findings)
