## Current State

- Manifest packages must be unique **exact** pins (`npm:<name>@<x.y.z[-pre][+build]>`):
  `config.py:11-14` (`_VERSION`, `_EXACT`), enforced in `load_manifest`
  (`config.py:151-155`), the planner (`planner.py:228`), `service.py:119`, and
  ownership state (`state.py:179`).
- `docs/pi-handler.md:89-95` states the hub does **no** version discovery or npm
  invocation. Pi, not the hub, runs npm for installs.
- `agentic-hub pi apply` already knows how to move a hub-introduced package to a
  new pin (`planner.py:266-276`, docs "Version changes use install with the new
  exact pin"). Adopted packages reject version changes (`planner.py:267-270`).
- CLI: `cmd_pi` (`cli.py:170-205`) dispatches `doctor`/`apply`/status;
  subparsers built in the loop at `cli.py:241-253`.
- `pi/manifest.json` is hand-formatted (packages on one line, inline arrays in
  `settings`); `json.dump` would reformat it.
- Atomic file replace exists only inside `state.atomic_json` (`state.py:318-343`),
  which is JSON/snapshot specific.
- Test harness: `tests/conftest.py` `isolated_pi_home`/`fake_pi` (fake `npm` is
  `exit 0`), per-feature files `tests/test_pi_*.py`.

## Design Decisions

- **`bump` edits the manifest only; `apply` stays exact and deterministic.**
  Rationale: keeps ownership tracking, dry-run (network-free) and the
  Pi-1.4.0 persistence gate intact; "latest" becomes a reviewable git diff.
- **Version source: `npm view <name> version`** (the registry's `latest`
  dist-tag, so prereleases are never chosen unless they are the tag). Uses the
  user's own npm/`.npmrc` (private registries work). Argument vector, no shell,
  neutral temp cwd, 30 s timeout, stdin discarded.
- **Resolve all, then write once.** Any lookup failure or malformed output aborts
  with exit 1 and leaves the manifest untouched.
- **Textual replacement, not re-serialisation**: replace the exact JSON string
  `"npm:<name>@<old>"` with `"npm:<name>@<new>"` in the file text, preserving
  formatting. Each source is unique (manifest validation), so it must occur
  exactly once; otherwise abort.
- **`--dry-run`** prints the planned changes without writing (mirrors
  `apply --dry-run`). Default writes.
- **Lock/state untouched**: bump never reads or writes settings, state or lock.
- Atomic write via a small tempfile + `os.replace` in the manifest's directory
  (`state.atomic_json` is not reusable for raw text).

## Risks & Mitigations

- Latest package may need a newer Pi than 1.4.0 → bump only changes the manifest;
  `pi apply --dry-run`/`doctor` still gate package mutation. Docs say so.
- Latest < current pin (current pin is a prerelease ahead of `latest`) →
  printed as `old -> new` for review; no automatic skipping. Documented.
- Supply chain (new version runs third-party install code) → `bump` never
  installs; installing needs an explicit `apply` after reviewing the diff.
- npm missing/offline → clear sanitized error, manifest untouched.
- Hand-edited manifest layout where the source string appears 0 or >1 times →
  abort rather than guess.

## Implementation Phases

1. **`bump` module + tests** — resolve latest, rewrite manifest text.
2. **CLI + docs** — `pi bump [--manifest] [--dry-run]`, update `docs/pi-handler.md`.

### Phase 1 — `src/agentic_hub/pi_handler/bump.py`

**Overview:** pure-ish module: `latest_version` (subprocess boundary) and
`bump_manifest` (read, resolve, rewrite).

**Changes**

- New `src/agentic_hub/pi_handler/bump.py`:
  - `@dataclass(frozen=True) class Bump: name: str; old: str; new: str`
  - `def latest_version(name: str) -> str` — runs
    `["npm", "view", name, "version"]` via `subprocess.run(..., cwd=tempdir,
    stdin=DEVNULL, capture_output=True, text=True, timeout=30, check=False)`;
    `shutil.which("npm")` missing → `ValueError("npm not found on PATH")`;
    non-zero exit, timeout, `OSError`, or output not matching
    `config._VERSION` (`re.fullmatch` on `stdout.strip()`) →
    `ValueError(f"cannot resolve latest version of {name}")`. Child output is
    never included in the message (consistent with `runtime.RuntimeFailure`).
  - `def bump_manifest(path: Path | None, *, dry_run: bool) -> list[Bump]`:
    1. `manifest = load_manifest(path)` (validates; resolves default path).
    2. For each `source` in `manifest.packages`: `name = package_name(source,
       exact=True)`, `old = source.rsplit("@", 1)[1]`, `new =
       latest_version(name)`; collect `Bump` where `new != old`.
    3. If no bumps → return `[]`.
    4. Read text of `manifest.path`; for each bump, `old_s =
       f'"npm:{name}@{old}"'`; require `text.count(old_s) == 1` else
       `ValueError(f"cannot locate {name} pin in manifest")`; replace.
    5. Re-validate: `json.loads` of new text and run through `load_manifest`
       logic is overkill; instead write to a temp file next to the manifest,
       call `load_manifest(temp)` (proves schema/pins still valid), then
       `os.replace(temp, manifest.path)` unless `dry_run`; always remove the
       temp file on failure/dry-run. Preserve file mode (`shutil.copymode`).
- No changes to `config.py`, `planner.py`, `state.py`, `service.py`.

**Tests** (new `tests/test_pi_bump.py`; fixtures `isolated_pi_home`; monkeypatch
`bump.latest_version` for unit tests)

- Unit: rewrites only changed pins and preserves formatting byte-for-byte
  elsewhere (one-line `packages` array, inline `settings` arrays).
- Unit: already-latest manifest → `[]` and file bytes unchanged.
- Unit: `dry_run=True` returns the bumps but file bytes unchanged and no temp
  file left behind.
- Unit: one lookup raising `ValueError` → exception propagates, manifest
  unchanged even though other packages resolved fine (all-or-nothing).
- Unit: pin string absent/duplicated in the text (e.g. manifest
  `packages` also referenced in a `settings` string value) → `ValueError`,
  unchanged.
- Unit: scoped package (`@upstash/context7-pi`) and prerelease/build old pin
  are rewritten correctly.
- Boundary: `latest_version` with a fake `npm` script on PATH (pattern from
  `conftest.fake_pi`) asserting argv is `["view", name, "version"]`, cwd is
  not the manifest dir, and returns the stripped version; fake `npm` printing
  garbage / exiting 1 / missing → `ValueError` without echoing child output.

**Success criteria**

- Automated: `uv run pytest tests/test_pi_bump.py -q`; `uv run ruff check src
  tests`; `uv run ruff format --check src tests`; `uv run pyrefly check`
- Manual: none beyond Phase 2.

**What we're NOT doing:** semver range/major-version policy, per-package
allow/deny lists, prerelease channels or `--tag`, concurrent npm lookups,
honouring settings `npmCommand`, comparing old vs new to skip downgrades.

### Phase 2 — CLI and docs

**Overview:** expose the module and document the new, explicit npm invocation.

**Changes**

- `src/agentic_hub/cli.py`:
  - subparser loop `for name in ("status", "doctor", "apply")` →
    add `"bump"`; `--dry-run` added for `name in {"apply", "bump"}` (help for
    bump: "preview new pins without writing the manifest").
  - In `cmd_pi`, before the apply branch:
    ```python
    if args.action == "bump":
        try:
            bumps = bump.bump_manifest(args.manifest, dry_run=args.dry_run)
        except ValueError as error:
            print(f"Pi bump: error\n{error}", file=sys.stderr)
            sys.exit(1)
        for b in bumps:
            print(f"  {'would bump' if args.dry_run else 'bumped'} {b.name} {b.old} -> {b.new}")
        if not bumps:
            print("Pi bump: all packages already at latest")
        return
    ```
    with lazy `from .pi_handler import bump` next to the existing lazy import.
- `docs/pi-handler.md`:
  - Commands block: add `agentic-hub pi bump [--manifest PATH] [--dry-run]`.
  - Replace "No automatic version discovery, downloads, caching, or npm
    invocation is implemented by the hub." with: `apply`/`status`/`doctor` do no
    version discovery or npm invocation; only `pi bump` runs `npm view` and only
    edits the manifest; it never installs. Note latest may need a newer Pi than
    1.4.0 and that downgrades (prerelease pin ahead of `latest`) are possible.
  - Exit table: bump follows the same `0`/`1`/`2` meanings.
- `README.md`: one line if it lists pi commands (check with `grep -n "pi apply"
  README.md`).

**Tests** (extend `tests/test_pi_cli.py`)

- `pi --help` lists `bump`; `pi bump --help` shows `--manifest` and `--dry-run`
  (extend the existing parametrised help test).
- `cli.main(["pi","bump","--manifest",m,"--dry-run"])` with monkeypatched
  `bump.latest_version`: stdout has `would bump demo 1.0.0 -> 1.1.0`, manifest
  unchanged, exit 0 (no `SystemExit`).
- Same without `--dry-run`: manifest rewritten; subsequent
  `service.inspect_setup(m)` loads cleanly (new pin is valid).
- Lookup failure → `SystemExit(1)`, stderr contains `Pi bump: error`, manifest
  unchanged, and no `~/.pi` files created (snapshot helper in the file).

**Success criteria**

- Automated: `uv run pytest -q`; `uv run ruff check src tests`; `uv run
  ruff format --check src tests`; `uv run pyrefly check`
- Manual: in a checkout, `agentic-hub pi bump --dry-run` shows plausible
  `old -> new` lines for the three current packages; `agentic-hub pi bump`
  then `git diff pi/manifest.json` shows only the version strings changed;
  `agentic-hub pi apply --dry-run` plans `update package ...` for hub-introduced
  packages (or reports the documented adopted-version conflict for adopted ones).

**What we're NOT doing:** auto-running `apply` after bump, committing the
manifest, a `--package NAME` filter, a changelog/diff fetch for new versions.

## Assumptions (validate during implementation)

- `npm view <name> version` prints only the version for a single package with no
  extra lines in the user's npm version (validated by the fake-npm boundary test
  plus the manual check; garbage output is rejected by the regex anyway).
- `pi-subagents@0.82.1` currently adopted in settings will conflict on bump
  because adopted packages reject version changes (`planner.py:267-270`); user
  resolves by release → re-apply, as already documented. Validate in manual step.
